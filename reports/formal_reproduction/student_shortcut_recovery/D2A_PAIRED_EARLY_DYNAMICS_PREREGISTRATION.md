# D2A paired pretrained early-dynamics preregistration

Date: 2026-09-10

Control: `D2A_PAIRED_PRETRAINED_EARLY_DYNAMICS_400`

Status before observation: `PREREGISTERED_NOT_YET_EXECUTED`

## Question

Does the exact locked ConvNeXtV2 visual initialization, under otherwise
identical C2 training conditions, preserve useful visual and mixed-label
temporal structure during the first 400 attempted batches better than the
same architecture initialized randomly?

This is a new trained control. It does not weaken or replace the failed D2
zero-training decodability gate. The old D2 800-step experiment remains
forbidden.

## Paired arms and fixed protocol

- D2A-R: `student.visual_pretrained=false`, `audio_pretrained=false`.
- D2A-P: the same seeded full-model construction, followed only by offline
  replacement of `visual_encoder.backbone` with the exact locked
  `timm/convnextv2_tiny.fcmae_ft_in22k_in1k` state.
- Both arms share the same C2 visual squared-norm (`sum`) objective, static
  zero-LR strong-teacher target, BCE/text terms, architecture, seed 42,
  batch size 4, LR, weight decay, AMP, positive-LR-only clipping, and cosine
  epoch scheduler.
- Primary budget is exactly 400 attempted batches. Applied updates and AMP
  skips are reported separately.
- Both arms consume the exact same already-augmented batch tensor object at
  each attempt. The fixed sample-index plan is generated by an RNG independent
  of model initialization. Actual input hashes are stored at attempts
  1/10/50/100/200/400.
- Evaluation is validation-only at attempts 0/25/50/100/200/400. There is no
  test manifest, test evaluation, second seed, D3, or Full run.
- Step 400 is the only decision point; selecting the best of the six snapshots
  is forbidden.

The exact executable contract is
`configs/diagnostics/recovery/ov_orthkd_d2a_paired_pretrained_early_dynamics_400.yaml`.

## Recorded trajectory

Each checkpoint records visual-backbone, projected-visual, projected-audio,
fused, shared, decision, and logit temporal scales; visual/audio gate means;
visual/audio encoder gradient norms; clipping coefficients and AMP receipts;
validation AP/AUROC and predicted-positive rate; mixed pair-weighted
concordance; mixed within-video temporal-shuffle AP/AUROC drops; and
visual-zero/audio-zero causal responses. Raw validation prediction NPZ files
are retained on the GPU host for independent recomputation and are not added
to Git.

## Frozen step-400 gate

D2A-P must have `mixed_concordance(P)-mixed_concordance(R) >= 0.020`, and at
least two of:

1. D2A-P decision temporal standard deviation `>= 0.003`;
2. D2A-P mixed temporal-shuffle AP or AUROC drop `>= 0.010`;
3. D2A-P visual-zero mixed-concordance drop `>= 0.010`.

It must also satisfy `AP_val(P) >= AP_val(R)-0.020` and D2A-P predicted-positive
rate `< 0.98`.

A PASS authorizes only a separately reviewed extension of the same pretrained
arm to 800 applied updates. It never launches that extension automatically and
does not authorize test, D3, Full, or a second seed. A FAIL closes this exact
pretrained initialization under the current C2 objective.

## Known preprocessing provenance gap

The common experiment transform remains the repository's fixed
`Resize((224,224))` plus ImageNet normalization to preserve the single-variable
pair. The locked checkpoint's published eval metadata instead specifies
bicubic resize/center crop with `crop_pct=0.875`. The paper does not recover
that preprocessing detail, so this difference is recorded rather than silently
introduced into only the pretrained arm.

The paired runner writes an atomic `paired_resume.pt` only on the 5090 at each
registered snapshot. An SSH disconnect therefore does not stop the detached
worker; a machine/process interruption can restart from the last registered
snapshot without changing the batch plan.
